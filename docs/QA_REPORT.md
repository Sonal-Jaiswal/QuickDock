# QuickDock 0.9.0 — QA report

**Date:** 2026-11-09 · **Test machine:** Apple silicon Mac, macOS 27.2, **one display** ·
**Toolchain:** Swift 6.4 with Command Line Tools only (no full Xcode), built against the macOS 26.5 SDK.

The reports behind this summary are in `docs/qa/*.json`. They are regenerated by the commands at the end.

## How testing was done

| Layer | Method | Result |
| --- | --- | --- |
| Core logic | 89 unit tests, 16 suites (Swift Testing): `scripts/test.sh` | **89 / 89 pass** |
| Running app | Debug-only in-process QA harness (`Sources/QuickDock/App/QAHarness.swift`, compiled out of Release). It drives the real sandboxed app: real panel, real key events through the AppKit event loop, real `NSWorkspace`, real bookmarks. It uses an isolated data folder and defaults suite. | **86 / 86 checks pass** across 6 phases (incl. Quick Wheel) |
| Release bundle | Launched the actual Release `.app` and inspected its windows via the window server | Pass (see below) |
| Packaging | DMG build, `hdiutil verify`, mount, copy, signature check, Gatekeeper assessment | Pass, and Gatekeeper rejects as expected for an unsigned build |
| Website | `astro check` (0 errors, 0 warnings), static build, headless Chrome desktop render, DevTools-protocol mobile emulation at 390 px | Pass |

Why a harness instead of clicking: this session had no Screen Recording, Accessibility or Automation
permission, so the screen couldn't be captured and synthetic system-wide input couldn't be sent. The harness
captures only QuickDock's own windows, which needs no permission. That's also how the website screenshots
were made: they are real captures of the running app, not mockups.

## Issues found during QA and fixed
0. *(Quick Wheel round)* Clipboard history used complete file protection, so saving failed while the Mac was locked. This was caught by a unit test while the screen was locked. **Fix:** a normal atomic write; the container is already protected by the sandbox and FileVault.
1. Item dates lost sub-second precision on save, so loaded items didn't equal saved ones. **Fix:** dates are normalized to whole seconds.
2. Safari was recorded at its internal cryptex path, and `/Applications/Safari.app` (a symlink) was classified as a file. **Fix:** items are classified by symlink target, keep the familiar path, and the regression test was added.
3. Symlinked apps showed an alias arrow on their icon. **Fix:** icons come from the resolved path.
4. Light-mode launcher text had low contrast on Liquid Glass. **Fix:** an appearance-aware glass tint.
5. Settings: "1 items" pluralization; the sidebar label was truncated; the editor needed scrolling. All fixed.
6. The uninstall script failed hard on the protected container. **Fix:** it handles this gracefully and explains.

## Known limitations / open items
- **Lingering process (once):** one launch-test run wrote its report but didn't exit, even after `timeout` sent SIGTERM. A manual SIGTERM later ended it normally, and six further runs exited on their own. The screen was probably already locked at that point. Not reproduced.
- **One unexplained hang:** the very first run of the launch-test phase never finished and wrote no report. The process sat idle in its run loop. Three later runs passed 7/7. It didn't reproduce, so the cause is unknown; it may have been a one-time system condition on first launching other apps from the sandbox. Worth watching in early testing.
- Unsigned build: users must approve it once in Privacy & Security. Updates replace the app with a new ad-hoc signature. Bookmarks survived this in testing; if not, Settings › Data › Restore File Access recovers them.
- Apple silicon only for now (`ARCHS="arm64 x86_64"` with full Xcode for universal).
- `hdiutil create/attach` print deprecation notices on macOS 27; they still work. A move to `diskutil image` can come later, but GitHub's older runners lack it.

## Reproduce
```sh
scripts/test.sh                                                         # unit tests
CONFIGURATION=debug scripts/build-app.sh
QUICKDOCK_QA=1 build/QuickDock.app/Contents/MacOS/QuickDock                         # full phase
QUICKDOCK_QA=1 QUICKDOCK_QA_PHASE=persist-check build/QuickDock.app/Contents/MacOS/QuickDock
# external files: open -W -n -a build/QuickDock.app --env QUICKDOCK_QA=1 --env QUICKDOCK_QA_PHASE=external-add <file> <folder>
#                 then QUICKDOCK_QA_PHASE=external-check QUICKDOCK_QA_UNGRANTED=<other file>
# real launching (opens Calculator, TextEdit, Finder, browser): QUICKDOCK_QA_PHASE=launch
# website screenshots: QUICKDOCK_QA_PHASE=screenshots
# Reports and captures: ~/Library/Containers/io.github.sonal-jaiswal.QuickDock/Data/tmp/quickdock-qa/
```
